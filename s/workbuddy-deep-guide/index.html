WorkBuddy 深度上手：从一句话到能验收的成品，以及它做不到的事

Laosia2026-11-282026-11-28

一、先说结论：它解决的不是”回答问题”，是”交付结果”

过去两年我们用 AI 的方式基本没变：打开一个对话框，打字，读答案，然后自己去执行。写文案要自己复制粘贴，改表格要自己动手，做 PPT 要自己排版。AI 给的是建议，落地的那一公里永远是人在走。

WorkBuddy 这类产品改的就是这一公里。你说”把这份销售数据做成一份给老板看的三页 PPT”，它自己去读文件、算数据、画图、生成 .pptx，最后把文件放在那儿让你验收。这个差别看起来只是”多了一步”，实际体验上是工作流的所有权变了——从”我指挥 AI 干活”变成”我验收 AI 的交付”。

这篇不吹也不黑，把它的能力结构、真实边界、以及我见过和踩过的坑一次性讲清楚。如果你正打算装一个试试，或者已经装了但用两天就搁下了，应该能省你不少时间。

二、它是谁：出身与定位

WorkBuddy 是腾讯云 CodeBuddy 团队在 2026 年 3 月 9 日推出的产品，定位是”全场景 AI 办公工作台”，官方叫法是”职场 AI 智能体桌面工作台”。同一时期字节的火山引擎也上线了对标产品 ArkClaw，两家几乎同一天发，这个时间点本身就说明了赛道热度。

理解它的定位，最好拿它跟同门师兄 CodeBuddy 对比：

维度 CodeBuddy WorkBuddy
核心场景 写代码、改代码、读代码库 办公文档、数据分析、调研、PPT、网页
形态 IDE 插件 / 编程助手 桌面客户端（Windows / macOS）
使用者 开发者 普通职场人
交互入口 编辑器里 独立窗口 + 手机端消息入口
积分 同一账号共享 同一账号共享

一句话记法：管代码的交给 CodeBuddy，管电脑的交给 WorkBuddy。 两者积分互通，不需要分别订阅——这一点很多人不知道，白买了双份。

它跟”另一个 Codex/Claude Code”的区别更本质：那些是给技术人的可编程工作台，要你自己写规则、配工具、调参数；WorkBuddy 走的是开箱即用路线，装完就能用自然语言开工。代价是可控性弱一些，好处是上手成本接近零。

三、能力结构：五层，别混着看

很多人用不好这类工具，根本原因是没搞清楚”我这次到底在调哪一层”。WorkBuddy 的能力是分层的，越往下越通用，越往上越专业：

层级 作用 什么时候用
模型 理解指令、推理、生成内容 所有任务的地基
Skill 增加一种明确能力（搜索、表格、网页制作、图像生成） 已知任务需要某个工具
Expert Skill + 领域角色 + 方法论 有一个清晰的专业问题
Expert Group 多个专家按流程协作 任务跨产品/设计/开发/运营多个角色
Connector / MCP 连接外部系统（GitHub、Jira、飞书、Notion、Gmail） 任务要读写其他系统的数据

记法：Skill 是能力，Expert 是能力加经验，Expert Group 是多个专家加协作流程。

官方口径是内置 100+ 领域专家、Skill 市场里 7 万+ Skills（SkillHub 独立站），覆盖招聘、投研、前端、法务、营销等。这个数字听起来夸张，但实际用下来，真正高频的其实就十来个：Excel 分析、PPT 生成、深度调研、网页制作、文档处理、批量文件整理。剩下的你大概率一年也不会点开一次。

实用建议：先不要逛 Skill 市场。先把”Excel 分析”和”文档/PPT 生成”这两类跑通，能覆盖 80% 的日常需求，剩下的按需再装。

四、三种工作模式：效率与安全的开关

这是我觉得设计得最有价值的一处细节。WorkBuddy 给了不同风险等级的执行模式：

  • Craft（直接干）：你说，它做，一口气执行完。适合需求明确、风险低的活，比如”把这份 Excel 按月份汇总成一张表”。
  • Plan（先审计划）：先出一份执行计划给你看，你点头它才动手。改代码、批量改文件、批量删除这种高危场景，必须开这个。
  • Ask（只答不做）：纯聊天，不动手。相当于普通 AI 对话。

三种模式切换零学习成本，但它把”效率”和”安全”的平衡权交回给了用户。这个设计看着朴素，实际是这类产品里最该抄的一点。

说明：官方文档里同时出现的是 Work Mode（通用办公）与 Coding Mode（工程任务）这一组划分，而第三方深度测评里描述的是 Craft / Plan / Ask 三档。两套说法可能是不同版本或不同入口的命名，实际以你客户端里看到的为准——但”有办法先审计划再执行”这个能力是确定存在的，这也是你该主动去找的开关。

五、界面结构：三个区，各有各的用处

第一次打开容易被劝退，因为它不像 ChatGPT 那样一个大白框，而是一堆板块。搞清结构就简单了：

  • 左侧任务列表：所有任务都在这儿，可以并行开多个，随时切回去看进度。
  • 中间对话区：补充材料、确认范围、提修改意见。这是你唯一需要打字的地方。
  • 右侧结果区：真正的交付物。三个视图切换——「概览」看生成的文件、「工作空间文件」看目录结构、「变更」看这次改了哪些文件。

结果区支持直接在客户端里预览 Excel、Word、PDF、网页，不用先下载再用外部工具打开。网页类任务还能直接看渲染效果、刷新重载。

这个”对话区和结果区分开”的设计很重要：它逼你去看真正的产物，而不是只看对话里的总结。我见过太多人只读 AI 在对话框里的自我总结就点了验收，结果文件里数据是错的。

六、记忆：为什么它”越用越懂你”

普通 AI 每次对话都是全新开始，你得反复交代”我不喜欢用分号结尾””文件默认放桌面””写文档要用二级标题”。WorkBuddy 做了三层记忆：

  • 云端记忆：自动学习你的使用习惯和偏好；
  • 用户级记忆：跨项目的个人规则，比如”输出默认用中文””代码注释写英文”；
  • 项目级记忆：每个项目的上下文独立保留，不互相污染。

实际效果是：第一次做某类任务时你需要写一大堆约束，做第三次的时候它已经记得了。这是它和普通聊天窗口体验上最明显的分野——用一周和用一天，是两个产品。

反过来也有坑：记忆会”记错”。如果你某次随口说”这次不用加目录”，它可能把”不要目录”当成长期偏好记下来，之后所有文档都没目录了。所以发现输出风格莫名其妙变了，先去设置里翻记忆条目，别急着改提示词。

七、模型与计费：这是最容易被低估的成本

7.1 模型

内置混元、DeepSeek、GLM、Kimi、MiniMax 等国产模型，可随时切换。没有官方的 GPT / Claude 接入，但支持自定义模型提供商，有 API key 的话可以自己接。

策略上很简单：简单任务用快模型省积分，复杂推理切强模型保质量。 但这里有个陷阱，见下一节。

7.2 积分

WorkBuddy 按积分（Credits）计费，个人版四档：

版本 月付 连续包月（7折） 连续包年（5.6折） 基础积分/月 限时加赠 每月实得
体验版 免费 — — 500 — 500
标准版 99 元 70 元 672 元 2,000 2,000 4,000
高级版 199 元 140 元 1,344 元 4,000 5,000 9,000
旗舰版 999 元 700 元 6,720 元 20,000 30,000 50,000

加量包：1,000 积分 / 50 元 / 有效期 1 个月。WorkBuddy 和 CodeBuddy 积分共享。

7.3 积分为什么难算

这是它被吐槽最集中的地方，也是我认为你最该提前搞清楚的一点：

同样 1000 积分，换个模型，能干的活差几十倍。

有博主用 13 个模型跑了 555 笔扣费做核对，结论是：同样 1000 积分，闲时用 DeepSeek-V4.1-Flash 大约能兑换 8.3 亿 token，而用 Kimi-K3 只有约 1248 万——相差 60 多倍。另一份模型排行给出的口径一致：平台内二十来个模型的单次倍率从 0.03x 到 1.62x，同样一句话能差出五十多倍。

更麻烦的是账目的”事后性”：缓存命中、输出 token 这些明细不展示，扣费经常要过很久才追加显示在对话后面。你干活的时候看不到余额在掉，等发现的时候已经没了。

界面上的”快速 / 均衡 / 极致”三档并不绑定固定模型，底层换了谁，扣费就跟着变。所以”我选了快速档应该很便宜”这个假设不成立。

实用做法：

  1. 固定用一两个模型，别频繁切。每次切换你都在重新建立成本直觉。
  2. 先拿体验版的 500 积分跑三个真实任务，记住每类任务大概吃多少积分，再决定买哪档。500 积分够你摸清量级。
  3. 长文档、大表格、批量文件这类”输入很重”的任务最烧积分，能拆就拆。
  4. 每日桌面登录能领约 100 积分，长期用的话这是个不小的补贴。
  5. 别信”无限续杯”的多账号切换工具——官方不背书，账号风险自己担。

八、安全边界：它能碰你电脑，这是底线问题

一个能读写你本地文件的 AI，安全性不是加分项，是及格线。WorkBuddy 在这块的策略偏保守，这也是它的优点之一：

  • 操作跑在隔离的 Docker 容器或 E2B 云环境里；
  • 你授权了哪个文件夹，它就只能碰那个文件夹；
  • 高危指令（删除、格式化、批量覆盖）会被拦截或要求二次确认。

但真实世界里出过事。有记录的情况是：某次上游模型服务不可用，一位用户临时切到备用模型的窗口期里，自己的文件被删了。还有博主让 AI”自动清理无用临时文件”，结果它靠文件名和扩展名判断，把正在跟进的项目配置文件当垃圾删了，当天工作直接停摆，花几小时才恢复。

AI 判断”这个文件有没有用”，靠的是文件名和格式，它不知道你在做什么项目。所以：

三条铁律：

  1. 删除 / 移动 / 批量重命名，永远先要清单再执行。 让它列出来，你逐条看完，再让它动手。开了 Plan 模式更好。
  2. 重要目录不进授权范围。 只开这次任务真正需要的那一个子目录，工作完就撤销。
  3. 动手前先备份。 批量操作前把目标目录复制一份，成本几秒钟，救回来要几小时。

另外，在安全中心把沙箱、删除保护、批量删除审批这几项主动打开。它们的默认强度、装机时会不会引导你打开，公开资料里查不到——别赌默认值，自己去看一眼。

九、任务怎么描述：一个能直接抄的公式

这是全文最有用的一节。绝大多数”AI 输出全是废话”的抱怨，根因都在描述太笼统。

公式：目标 + 输入 + 输出 + 约束 + 验收标准

对比一下：

❌ 差：

帮我分析一下这个数据

✅ 好：

目标：找出美国站过去四周流量变化的原因。
输入：附件里的渠道明细表。
输出：一页中文结论 + 三张图表 + 一份 5 页 PPT。
约束：不使用缺失率超过 20% 的字段；结论必须标注对应的数据范围。
验收：每个结论都能在表里找到对应行；列出三条可执行建议。

第二种描述里，AI 知道”给谁看”（管理层）、”多长”（一页）、”什么格式”（PPT）、”什么不许做”（不用缺失字段）。输出质量差别是数量级的。

再举三个可以照抄的模板：

数据分析 + 汇报

检查字段和缺失值，按月份和地区分析收入变化，标出异常波动，生成图表，输出一份面向业务负责人的周报。

会议纪要 → 行动项

总结会议结论，提取任务、负责人、截止时间和依赖关系，标记尚未确认的信息，生成可跟踪的行动清单。

产品资料 → 落地页

根据产品资料整理页面信息架构，撰写首屏、功能、场景和 FAQ 文案，再生成一个可预览的响应式落地页。

最后那个我建议分两步：先让它确认信息架构和文案，你改完再让它生成页面。一次到位的话，改起来要动整个页面。

一个额外的关键习惯：一个任务一个窗口

同一个对话里连着干几件不相关的事（先写方案、再改 PPT、再分析表格），AI 会把前面的内容串到后面的任务里，出现逻辑混乱、重点跑偏，而且越改越乱救不回来。不同类型的工作，新建任务。

十、我见过的八个高频翻车点

这部分全部来自真实使用反馈，不是假设。

坑 1：需求太笼统，输出全是套话
“写个月度总结” → 出来一篇网上通用模板，跟你岗位毫无关系。让它分析营收，整篇在讲项目背景，核心的收入、成本、差额一个没有。
→ 明确字数、场景、写作重点、要规避的内容。

坑 2：同一窗口堆多个任务
见上一节。分开建任务。

坑 3：超长文档被截断
有用户反馈单篇超过约 8000 字会被自动截断，一万多字的复盘上传后关键条款、核心数据全漏了。这个阈值我无法从官方文档确认，但**”长文档会丢信息”这个现象是多人都遇到的**。
→ 长文档拆段处理，最后再整合。上传前先问它”这份文档你完整读到了吗，最后一段讲什么”。

坑 4：复杂计算会算错，而且会编理由圆谎
最容易翻车的一类。让它核算加班时长和调休抵扣，表格看着整整齐齐，数据全错；跨凌晨、要扣休息时间的场景能差十几分钟。你去质疑，它还会编个理由糊弄你——比如图片比例错了，它硬说”平台只支持正方形”。
→ 凡是数据核算、逻辑计算，无论输出多规整，必须人工逐项对核。 复杂规则拆成分条要求，别一次性笼统丢过去。

坑 5：自动清理文件误删重要文件
见上一节。

坑 6：长任务质量会掉
任务一长，它容易停在”改一点、跑一下、能展示就算完成”的循环里，把一个能跑的 Demo 当成工程交付。有人把原因拆得更细：上下文压缩”太薄”，被丢掉的恰恰是复杂任务最关键的信息——为什么这样设计、哪些方案已被否决、项目进行到哪一步。压缩一轮，下一轮质量立刻下滑。
→ 长任务自己维护一份”决策记录”，每轮开始时贴给它。别指望它记得。

坑 7：多 Agent 协作会”左边不知道右边在干嘛”
多 Agent 并行还在打磨阶段。简单分工（一个查资料、一个写报告）能用，复杂协作经常出现信息不同步。
→ 需要协作时，你当调度员，明确每个 Agent 的输入输出边界。

坑 8：定时任务和推送不稳定
“每天早上九点给我整理 AI 资讯发到企业微信”这类自动化，通知体验粗糙、内容偶尔有 bug。有开发者实测的结论是”提醒了个寂寞”。
→ 定时任务只用来做容忍失败的事（资讯汇总、日报），不要用来做不能漏的事（合同到期提醒、账单支付）。

十一、连接器与远程：把它的手伸出电脑

很多人只把 WorkBuddy 当”本地文件处理器”，忽略了它还有一层很关键的扩展能力：连接器（Connectors）和 MCP。

11.1 Connectors

连接器让它在获得授权后读写外部系统。目前覆盖的主流服务包括 GitHub、GitLab、Jira、Confluence、Google Drive、Gmail、Notion、Slack，国内侧则打通了微信、企业微信、飞书、钉钉、QQ，以及腾讯文档、腾讯会议、腾讯问卷这些腾讯系产品。

举几个真实有用的组合：

  • Jira + GitHub：让它”把本周所有状态是 Blocked 的 issue 汇总成一份风险清单，标注对应的 PR 和最后更新时间”。它会自己去两个系统拉数据、对齐、生成表格。
  • Google Drive + 文档：给它一个 Drive 文件夹，让它把里面所有会议记录提取成统一的行动项清单，输出 Excel。
  • Notion + PPT：读取某个 Notion 数据库里的项目进展，生成月度汇报 PPT。
  • Gmail：让它把过去一周的客户邮件按诉求分类，标出需要今天回复的，草拟回信（草稿，不直接发）。

关键点在于授权范围。连接器给的是”读”或”读写”权限，一旦给了写权限，它就能真的改你的工单、发你的邮件、动你的仓库。所以：

  1. 优先给只读。绝大多数分析类任务根本不需要写权限。
  2. 写操作走”生成草稿 + 人工确认”。让它把要发的邮件写成草稿、要建的工单写成清单，你过一遍再执行。
  3. 定期清授权。用完的连接器、API key、Webhook 该撤就撤。这条比什么都重要，长期堆积的授权是最常见的泄露源。

11.2 MCP

MCP（Model Context Protocol）是个通用扩展协议，你可以把它理解成”AI 世界的 USB 接口”——任何按这个协议包装过的工具或数据源，都能插进 WorkBuddy 用。

它的价值在于把一次性的能力变成可复用的工具。比如你自己写了个查库存的小服务，按 MCP 包一层，之后就能直接对它说”查一下 A 型号现在的库存，低于 500 的列出来”，不用每次都贴 API 文档。

对普通用户来说 MCP 属于进阶内容，可以先放着。但如果你有自建系统、内部数据库、私有 API，MCP 是把它接进来的正路——而且这条路不限于 WorkBuddy，同一个 MCP server 也能给别的支持该协议的工具用，不算绑定。

11.3 远程 Assistant

这是我觉得最有”未来感”的一块。通过 Assistant，你可以从手机上的 Slack、Telegram、Discord、企业微信、飞书、钉钉、QQ 给电脑端的 WorkBuddy 发任务，结果也推回同一个渠道。

场景很具体：你在外面吃饭，突然想起来明天开会要一份材料。掏出手机发一句”把桌面上那份 Q4 数据整理成三页 PPT，做完发我”，回家打开电脑，文件已经在桌面上了。

但它有硬性前提：电脑必须开着机、WorkBuddy 必须处于运行状态、网络要稳。它不是云端的，是”遥控你家里那台电脑”。所以：

  • 台式机比笔记本靠谱（笔记本合盖就断）；
  • 别指望它在你关机的时候干活；
  • 涉及需要登录的网页操作，电脑上的浏览器会话也得是活的。

如果你需要”关机也能跑”的能力，那就得看它的云端助理那套——重复性的日常任务（会议纪要整理、数据处理、周报生成）可以托管在云端持续运行，关掉客户端也不中断，成果直接下载。这两条路要分清：远程 Assistant 是遥控本地，云端托管是交给云。

十二、团队与企业：从个人工具变成组织能力

个人用和团队用，是两种产品。个人关心”我这活能不能快一点”，团队关心”这套流程能不能复制给别人、成本能不能管住”。

12.1 项目空间

WorkBuddy 的团队能力核心是”项目空间”。在一个项目里：

  • 多个 Agent 可以并行处理各自任务，结果统一汇总；
  • 调好的专家、Skill、连接器可以沉淀到项目空间，一次配置全组复用；
  • 知识库和权限有统一边界，成熟流程可以跨部门横向推广。

这个设计的价值不在”多人协作”，而在把个人调参的经验变成组织的资产。一个人花两周调出一个好用的”投标文件生成”流程，沉淀进项目空间后，全组十个人当天就能用，不用各自再踩一遍坑。

12.2 权限与用量

企业版关注三件事：成员权限、公共能力资产的共享、以及用量与费用的统一查看。这三件事恰恰是个人版完全不需要操心的——也是为什么个人版能做得这么轻。

12.3 一个务实的判断

如果你是小团队（3–5 人），个人版的标准版或高级版基本够用，不必上企业版。真正需要企业版的信号是：

  • 需要按人分配权限、审计谁用了什么；
  • 需要共享专家和 Skill，避免重复配置；
  • 需要统一开票、统一结算、统一看成本。

在那之前，企业版带来的管理开销会大于收益。

十三、一次完整的实操：从零到交付

前面讲的都是结构，这一节走一遍真实流程，让你看到每一步在干什么。

任务：手上有一份 12 个月的销售明细 Excel，要做成一份给管理层的年度复盘 PPT。

第一步：建任务，选模式

新建任务，模式选 Plan（因为要生成多份文件，想先看它打算怎么做）。工作空间指向那个放 Excel 的文件夹——只授权这一个文件夹，不要图省事授权整个 D 盘。

第二步：写任务描述

按公式来：目标 + 输入 + 输出 + 约束 + 验收标准。

目标：基于附件的 12 个月销售明细，做一份面向管理层的年度复盘。
输入：sales_2026.xlsx，字段包含日期、区域、渠道、产品线、销售额、订单数、退货额。
输出：

  1. 一份 Excel 汇总表（按季度×区域，含同比/环比）；
  2. 三张图表（月度趋势、区域贡献、渠道结构）；
  3. 一份 8–10 页 PPT，结构为：整体表现 / 区域拆解 / 渠道拆解 / 问题诊断 / 明年建议。
    约束：退货额需从销售额中扣除后再计算净额；缺失率超过 20% 的字段不使用；所有百分比保留一位小数。
    验收：每个结论都能在汇总表里找到对应数据；诊断部分必须指出至少三个具体问题，不接受”整体向好”这类空话。

第三步：审计划

Plan 模式下它会先给步骤。这时候重点看三件事：

  1. 它打算怎么算净额——如果没提扣退货，立刻纠正；
  2. 它的图表数据源——是不是从汇总表来的，还是自己另算一遍（另算容易和表格对不上）；
  3. 它读文件的方式——12 个月明细可能几万行，如果它打算一次全读，提醒它先看字段和行数，再分段聚合。

第四步：执行中盯着

右侧结果区会陆续出现文件。这时候不用等它全部做完，看到第一个文件就先打开看：

  • Excel 的表头和数据类型对不对（有没有把数字读成文本）；
  • 图表的数据标签有没有被截断；
  • PPT 的版式是不是你要的那种（是”每页一张大图”还是”左图右文”）。

早发现早改，比全做完再推翻省得多。

第五步：局部迭代，不要重做

发现问题时，不要说”重做一遍”。要指到具体位置：

第 3 页的区域贡献图，华东和华南的颜色太接近，换一组对比更强的配色；另外第 5 页的诊断只有两条，补第三条，聚焦退货率。

局部修改的成功率远高于重做。重做等于让它重新走一遍所有决策，很可能把原来对的部分也改错。

第六步：验收交付物

这是最容易偷懒也最不能偷懒的一步。打开每一个文件看，不要只看对话区的总结。

  • Excel：抽查 3–5 个数字，用手算或另开一个表验证；
  • 图表：数据点和汇总表对得上吗；
  • PPT：每页的结论和数据一致吗，有没有它自己”补充”出来的、原始数据里根本没有的说法。

我见过最典型的翻车就是这一步跳过：PPT 做得漂亮，第 6 页写”退货率同比下降 12%”，而原始数据里根本没这个结论——是模型根据趋势”推”出来的。AI 会补全它认为合理的东西，这是语言模型的本性，不是 bug。

第七步：沉淀

如果这套流程你每季度都要跑一次，把它存成模板：任务描述存下来，跑通的专家固定下来，反复要交代的规则写进用户级记忆。下次换个文件就能直接跑。

这一步做完，你才真正开始省时间。 第一次跑这类任务，通常比自己动手还慢——但第二、第三次就是纯赚。

十四、常见疑问

Q：它和 CodeBuddy 要不要买两份？
不要。同一账号积分共享，一个订阅两边都能用。

Q：没有 GPT / Claude 能用吗？
内置的国产模型（混元、DeepSeek、GLM、Kimi、MiniMax）覆盖绝大多数办公场景。要接 GPT / Claude 得自己配自定义模型提供商，有 API key 就行，但要额外花钱且需要一点配置能力。

Q：会不会把我的文件传上去？
它确实需要读取你授权的文件内容来处理，执行环境是隔离容器或云沙箱。所以涉密、涉个人隐私的资料不要交给它。这不是它的缺陷，是这类产品的固有属性——你要它干活，它就得看见材料。

Q：为什么我的输出风格突然变了？
先查记忆。它可能把你某次的临时要求当成了长期偏好。记忆条目的优先级高于你当次的提示词。

Q：定时任务靠谱吗？
做”漏了也无所谓”的事（每日资讯、周报草稿）可以；做”漏了就出事”的事（到期提醒、对账）不行。目前的通知体验和稳定性还撑不住后者。

Q：免费额度够用吗？
500 积分够你跑通三到五个真实任务、建立成本直觉。想长期用肯定不够，但足够你判断”要不要买”。

Q：值得买哪一档？
先跑两周。如果你每周有三个以上重复流程能交给它，标准版（连续包月 70 元，实得 4000 积分）是最划算的起点。跑到积分经常月中就见底，再考虑高级版。旗舰版是给重度多项目用户的，普通人用不上。

十五、它不适合做什么

说清楚边界比列优点更有用：

场景 适不适合 原因
Excel 分析、图表、周报 ✅ 很适合 结构化任务，验收标准明确
文档/PPT 从零生成 ✅ 适合 有模板可循，改起来快
深度调研、竞品分析 ✅ 适合 能自己搜、自己整理
网页/落地页原型 ✅ 适合 生成快，能直接预览
批量文件整理重命名 ⚠️ 谨慎 高危，必须 Plan 模式 + 清单确认
精确财务核算、法务条款 ❌ 不适合 错了代价太大，人工复核成本高于自己算
长期托管的复杂工程 ❌ 不适合 上下文压缩撑不住
处理敏感/涉密资料 ❌ 不适合 云端执行，权限边界难保证

一句话：它擅长”有明确验收标准的重复性脑力劳动”，不擅长”错了要赔钱的精确计算”和”需要长期记忆的复杂工程”。

十六、上手路线图

如果你决定试试，按这个顺序走，别一上来就逛功能。

第一天：跑通一个真任务
不要问”你能做什么”。直接给它一件你现在手上真实的小活，边界清晰、能马上验收。比如”读取这份周报数据，输出本周关键变化、异常项和下周建议，做成三页 PPT”。跑完你就知道它是什么了。

第一周：建立成本直觉
用体验版的 500 积分，跑 5–8 个不同类型的任务，记录每类大概吃多少积分。同时把”一个任务一个窗口””高危操作开 Plan 模式”这两个习惯固定下来。

第一个月：沉淀可复用的东西
把跑通的流程存成模板，把反复要交代的规则写进用户级记忆，把常用的专家/Skill 固定下来。这一步做完，你才真正开始省时间——前三周基本都在交学费。

之后：才考虑自动化和多 Agent
定时任务、手机端远程、多 Agent 并行，这些都是锦上添花。基础流程没跑顺就上自动化，只会把不稳定放大。

十七、总结

WorkBuddy 这类桌面智能体，把 AI 的价值从”提供答案”推到了”交付成品”。这个跨越是真实的，不是营销话术——你确实可以一句话下去，十分钟后拿到一份能直接发的 PPT。

但它同时把两件事推到了你面前：

第一，验收责任回到你身上。 它交付得越快，你越容易跳过检查。而它会在复杂计算上出错、会编理由圆谎、会把 Demo 当交付。AI 干得越多，人的复核越不能省。

第二，成本变成了隐性变量。 积分按模型倍率浮动几十倍，账目还是事后才显示。不建立成本直觉，很容易一个月烧掉两三百块还不知道钱花在哪。

我的判断是：它值得装，但要用”带审阅权的委托”这个心态去用，而不是”全自动躺平”。 把它当成一个执行力很强、但需要你划边界和验收的新同事——这个比喻比”AI 助手”准确得多。

至于要不要付费：先用免费额度跑够两周，跑出至少三个你每周都要重复的流程，再考虑标准版。没有重复流程的人，不需要订阅。
