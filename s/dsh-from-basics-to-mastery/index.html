DeepSeek Harness 从入门到精通

《DSH 零基础全流程教学》解决的是”装好、能对话、会许愿”；这一篇往上走一层：它到底是什么架构、每个开关在管什么、出问题该看哪个文件。

DSH 全名 DeepSeek Harness，是 DeepSeek 开源的 agent harness（智能体框架），GitHub 上 deepseek-ai/deepseek-harness 已经 28 万星，MIT 协议，官方自我定位只有一句：

Everything is a Plugin.

它现在还标着 开发者预览——会出破坏性变更，也意味着你看到的界面和配置项随时可能变。这篇里所有命令和字段都来自官方仓库的文档（docs/user/），不是猜的。

一、先建立正确的心理模型

多数人把 DSH 当”能操作电脑的 ChatGPT”，用起来就会处处别扭。正确的分层是这样：

层 是什么 对应现实
模型 DeepSeek 的模型（或你接的第三方） 大脑，负责推理
Harness DSH 本体：会话、工具调度、权限、上下文管理 身体和神经系统
插件 一切功能的最小单位，连”读文件””跑命令”都是插件 器官
Skill 把固定几步流程封成一条指令 肌肉记忆
MCP 接外部工具/数据源的协议 外接线缆
Preset / 模式 预置的插件组合 + 提示词 + 工具集 工作服

底层用的是 Cordis 这个插件框架，所以 DSH 里没有”内置功能”和”插件功能”的区别——你在界面上看到的每一个按钮、每一种模式，都是某个插件行加载出来的。理解这一点，后面所有配置都通顺了。

2）无头模式（脚本、CI、定时任务用这个）

一句话任务，跑完打印结果就退出。常用参数：

参数 作用
--json 逐行输出运行事件（结构化，给程序读）

三、五个必设项，决定它好不好用

装完第一件事不是聊天，是把这五项配好（桌面端在设置里，Web UI 在左下角/侧栏）：

项 建议 为什么
工作区 指向你真正要它干活的项目目录 它的文件读写以工作区为根，选错地方等于让它瞎逛
模型 DeepSeek 最新的 Flash 系（多模态） 支持看图，截图扔给它排错是最高频用法
推理等级 日常 high，贵任务 max 见第五节，这直接决定质量和成本
权限 先”工作区内修改”，装东西失败再开”完全权限” 完全权限 = 不再逐条确认，风险自负
预设/模式 日常 标准 PTC 用于批处理、极简用于测模型、创造用于写插件

密钥存哪：$DSH_HOME/.credentials.yaml（$DSH_HOME 默认 ~/.dsh）。它是只写的——设置页保存后再也不会把明文吐回来，只给一个脱敏描述符。所以密钥丢了只能重填，别指望从配置文件里翻出来。

五、模型层吃透：这是”精通”的分水岭

5.1 接自己的网关

设置 → 模型 → 添加模型提供商。除了 DeepSeek 官方，内置目录里还有 anthropic、openai、moonshotai（Kimi）、zai（GLM）等，填个 key 就能用。

中转站 / 自建网关 / 公司内网选 自定义模型 API，四个字段：Provider ID（永久不可改，因为会话和凭据引用都记着它）、基础 URL、API 协议、密钥。

协议只能选一种，选错必然全挂：

协议 配置值 说明
OpenAI Chat Completions openai-completions 最常见的兼容网关
OpenAI Responses openai-responses 新版 OpenAI 式接口
Anthropic Messages anthropic-messages Claude 系
Gemini API google-generative-ai 基础 URL 要含版本，如 /v1beta

怕模型 ID 填错？点 获取可用模型 让它打一下端点的 GET /models；打不通就手填，效果一样。

5.3 两个必知的兼容开关

密钥对、地址通，网关却拒绝每一个请求，九成是这两条：

症状 原因 修法
所有请求 400 系统提示词用 developer 角色发出，网关不认 compat.supportsDeveloperRole: false

写在 provider（对全部模型生效）或单个 model 下（只覆盖该模型）都行。

六、四种模式，四种用法

输入框上方那个”标准模式”是可切换的预设。官方定义 + 实际用法：

模式 它到底做了什么 什么时候用
标准 全套工具（检索、编辑、终端），按需调用 90% 的日常任务
PTC 在标准能力之上，专门优化”批量调用工具后筛选/去重/统计/汇总” 一次处理几十上百个文件、批量抓数据后汇总
极简 只给终端和读图工具，带上下文压缩 想对比模型本身实力，或要极省 token
创造 让 Agent 写插件、改界面、组合出自己的模式 一句”做个 XX 插件”

创造模式是 DSH 最有意思的地方：它把这个应用变成了可被你改写的软件。官方给了一批提示词，比如”创建一个带左侧边栏入口的插件，用 3D 展示埃菲尔铁塔/长城/紫禁城”、”做一个基于我真实会话数据的统计插件，展示 token 消耗与成本”。

配合同一个功能还有一个工具 plugin_market（只在创造模式下可见，且需要先开”自定义插件索引”开关）。

七、权限与审批：别把安全当可选项

权限策略决定”它做什么之前要不要问你”。三个层次的取舍：

策略 体验 风险
每次确认 最安全，最烦 长任务会打断几十次
工作区内修改（推荐日常） 改文件自动、装东西/碰系统外要问 中等
完全权限 全程不问，跑得最快 它能改你系统任何地方

两条硬经验：

  1. 装插件、装环境时用完全权限，否则它会卡在”这一步要不要执行”上反复失败；
  2. 跑不可逆操作时（清理磁盘、删目录、改注册表）先降回逐条确认，并且让它先给你清单、你过一遍再放行。

无头模式（dsh headless）里权限是启动参数，不是界面开关——--permission-mode 选预设，--approval-policy 决定审批行为。定时任务里跑的东西，权限一定从紧。

八、扩展的三层：插件 / Skill / MCP

一句话区分：

  • 插件：装上就多一个功能（像 App）；
  • Skill：把几步流程封成一条指令（像快捷指令）；
  • MCP：把 DSH 接到外部系统（像数据线和蓝牙）。

8.3 自己写插件：最小可用只要 10 行

插件就是一个导出 apply(ctx) 的模块：

三个进阶点：

要什么 怎么写
用到别的服务 export const inject = ['tools']，框架会等依赖就绪再加载
注册一个工具 ctx.tools.register(defineTool({ name, description, parameters, output, execute }))
要手动清理的资源 ctx.effect(() => { const t = setInterval(...); return () => clearInterval(t) })

通过 ctx 注册的一切（事件、工具、定时器）会在插件卸载时自动清理，不用手写 removeListener——这是 Cordis 最省心的地方。配置变更会触发热替换：旧实例卸载、新实例加载。

让插件可配置：导出一个 Config 类型 + 同名 Schemastery schema，默认值写在 schema 里，不合法会在加载时报错。约定是：凡是不同部署可能要改的值，都必须做成配置字段，不许硬编码。

8.4 打包成可安装的 bundle

概念 回答的问题 manifest
bundle（组合包） 这个包贡献什么？ package.json 里的 dsh.bundle.patch
profile 这套配置由哪些包按什么顺序组成？ dsh.profile.bundles

装进 profile：

engines.dsh 一定要写——它声明兼容的 DSH 版本，装的时候和启动 profile 时都会检查，不匹配就拒绝。开发者预览期版本动得快，这一行能帮你少踩很多”装了但不生效”。

九、自动化：DSH 自己会定时干活

DSH 内置 Schedule 服务，四个工具：schedule_create / schedule_list / schedule_view / schedule_edit。standard、cordis、ptc 三个 preset 自带这四个工具，minimal 没有。

直接说人话就能建：

每天 Asia/Shanghai 23:00 提醒我查看天气。

它会用 RFC 5545 的重复规则建任务，界面上还有独立的自动化任务页面能看全部任务、改时间、暂停/恢复、立即执行、看运行记录。

几个必须知道的边界：

  • 宿主不跑，调度就停——DSH 不是云服务，电脑关机任务不会执行；重启后会补投逾期的一次性提醒，以及每条重复任务最近错过的那一次。
  • 同一提醒两次投递之间至少隔 1 分钟，每次新建对话的提醒还要等宿主的最小运行间隔。
  • 子 agent 不能碰提醒：被委派的 subagent 能看到这四个工具，但调用会被拒绝。
  • 投递只是把指令放进对话收件箱，不代表模型一定完成了那件事——要看运行记录里有没有后续。

要真正的”服务器级”定时，用 dsh headless + 系统 cron 更可控（跑完即退，不常驻）。

十、排错对照表（收藏这一节）

报错 / 现象 原因 处理
MISSING_CREDENTIAL 该 provider 没密钥也没环境变量 设置→模型里存密钥，或配 apiKeyEnv 指向的环境变量
UNKNOWN_MODEL 模型没在配置里 选已配置模型，或给自定义 provider 加模型
网关拒绝所有请求 请求形态不是 OpenAI 那种 先加 compat.supportsDeveloperRole: false + maxTokensField: max_tokens
只有推理模型失败 系统提示词走了 developer 角色 同上第一条
off 关不掉思考 端点默认就思考 加 compat.thinkingFormat: deepseek
手填模型没有推理等级菜单 没声明等级 模型选项里开”推理等级”，或写 reasoningEfforts
图片发不出去 模型没声明图片模态 加 input: [text, image]；DeepSeek 自家选支持图片的目录条目
带图请求被上游拒 声明了端点其实不支持的能力 去掉 image 后新开会话（旧会话日志里还留着那张图）
CLIENT_UPGRADE_REQUIRED 模型需要更新版 DSH 按提示升级
装插件失败 权限不够 先切完全权限，把报错原样丢给它自己修
上下文快满 会话太长 /compact；换任务就新开会话
索引装不上 索引文件不合规 看做索引源下面显示的具体违规路径
Profile 起不来 配置被改坏 dsh rescue --from-default-profile web

十一、成本与性能：怎么用才不烧钱

手段 效果
换任务就开新会话 避免历史无限累积，单轮 token 与延迟一起降
/compact 代替硬撑 长任务里定期压，比塞满再崩强
日常 high、难任务才 max 推理等级对成本的杠杆远大于换模型
批量活走 PTC 一次批量调用 + 汇总，比逐条对话省得多
极简模式做对比测试 只给终端和读图，快速判断”是模型不行还是提示词不行”
看缓存命中率 命中率长期很低 → 要么提示词顺序有问题，要么在频繁换会话
不给无用工具 用极简/自定义 preset，工具描述本身也占 token

十二、一张表看清”入门 / 熟练 / 精通”

层级 会做什么
入门 装上、配好工作区/模型/权限、用大白话让它整理文件、装环境、清磁盘
熟练 选对模式和推理等级；管上下文与会话；装插件与 MCP；用 Schedule 建提醒；按排错表自己修
精通 接自己的网关（协议/兼容开关/推理等级映射）；写插件并打包成 bundle 分发；用 headless + cron 做无人值守；用 --dump-config 体系调试合成配置；用跨会话消息搭多 agent 流水线

从”能对话”到”精通”，真正的分界线不是会多少提示词，而是知道每一层在管什么、出问题该改哪个文件。DSH 的配置文件就那一个（$DSH_HOME/profiles/<profile>/cordis.patch.yml），把它看成”插件行的清单 + 每行的 config”，整个系统就不再神秘了。
