Linux 入门必会命令：从登录到排障的 30 个基本功

Laosia2026-11-132026-11-13

适用系统：Debian / Ubuntu / CentOS / Rocky 等主流发行版（systemd 环境）
适用读者：刚接触服务器的新手，或者只会点面板、想真正上手命令行的人
原则：先会用，再会查，最后才记参数。命令不是背出来的，是用出来的。

一、先搞清三件事，比背命令重要得多

1.1 一条命令长什么样

  • 选项：以 -（短选项，可合并如 -lh）或 --（长选项 --human-readable）开头。
  • 参数：命令作用的对象，通常是文件、目录、用户名。
  • 命令、选项、参数之间必须有空格，ls-lh 会报 command not found。

1.2 不会用就查，别猜

命令 作用 例子
man ls 完整手册，q 退出，/ 搜索 man tar 查参数含义
ls --help 简化版帮助，输出到终端 tar --help
apropos 关键词 按功能搜命令 apropos compress
type 命令 它是别名、内置命令还是程序 type ll
which 命令 可执行文件在哪 which nginx

新手最常见的误区：遇到参数不懂就上网搜。其实 man 里全都有，只是英文。（新系统可以 sudo apt install manpages-zh 装中文手册。）

1.3 Tab 补全和上下键

  • Tab：补全文件名、命令名，按两下列出所有可能。这个键能省掉你 80% 的输入和拼写错误。
  • ↑ / ↓：翻历史命令。
  • Ctrl + R：反向搜索历史命令，输入片段就能翻出以前那条长命令。
  • Ctrl + C：中断当前命令（卡住了就按它）。
  • Ctrl + L：清屏（等于 clear）。

二、文件与目录：日常用得最多的一类

命令 作用 常用写法
pwd 我在哪 pwd
ls 看有什么 ls -lh ls -a ls -lt
cd 去别处 cd /etc cd .. cd ~ cd -
mkdir 建目录 mkdir -p /data/app/logs
touch 建空文件 / 更新时间戳 touch test.txt
cp 复制 cp -r 目录 目标
mv 移动 / 改名 mv a.txt b.txt
rm 删除 rm -i 文件

注意：cp a b 如果 b 是个已经存在的目录，文件会被放进 b/a，而不是覆盖 b。这个语义经常让新手懵。

2.3 rm 是唯一没有后悔药的命令

三条铁律：

  1. rm -rf 后面绝对不要跟变量，尤其是 rm -rf $DIR/* 里 $DIR 为空时，等于 rm -rf /*。
  2. 想删的东西先 ls 一遍确认，再动手。
  3. 重要的目录，把 rm 换成 trash-cli 或者先 mv 到 /tmp 放一天。

顺便记一下：Linux 没有回收站。图形界面里的“回收站”是桌面环境自己模拟的，命令行删除是直接 unlink。

三、看文件内容

命令 场景
cat file 短文件，一次看完
less file 长文件，可翻页可搜索
head -n 20 file 看开头 20 行
tail -n 20 file 看结尾 20 行
tail -f file 实时追日志，最常用
wc -l file 数行数

less 里必会的按键：

按键 作用
空格 / b 下一页 / 上一页
/关键词 向下搜索，n 下一个，N 上一个
g / G 跳到文件头 / 文件尾
q 退出

别用 cat 打开几百 MB 的文件——终端会刷屏到卡死，less 才是正解。

五、权限：rwx 和 755 到底在说啥

5.1 权限的两种写法

数字 含义
4 r 读
2 w 写
1 x 执行
7 4+2+1 = rwx
6 4+2 = rw-
5 4+1 = r-x

5.2 属主与属组

看到 Permission denied 时的正确顺序：先确认自己是谁（id），再看文件权限（ls -l），然后判断是该 sudo 还是该改权限。不要无脑 chmod 777 —— 那等于把门拆了。

六、你是谁：用户与提权

sudo 报错时按这两条排查：

  • xxx is not in the sudoers file → 该用户没有 sudo 权限，需要 root 加进 /etc/sudoers（用 visudo 编辑）。
  • 提示输入密码但你没设过 → 云服务器常见，用控制台的救援模式或密钥登录重置。

七、进程与服务：卡了、挂了、占资源了

7.1 看进程

top 第一行的 load average 三个数分别是 1、5、15 分钟的平均负载。判断标准：超过 CPU 核心数就说明在排队（nproc 看核心数）。

7.2 结束进程

顺序永远是：先 kill，等几秒，不行再 kill -9。直接上 -9 可能丢数据、留僵尸。

八、装软件：包管理器

发行版 更新索引 安装 卸载
Debian / Ubuntu apt update apt install 包名 apt remove 包名
RHEL / CentOS / Rocky dnf makecache dnf install 包名 dnf remove 包名
Arch pacman -Sy pacman -S 包名 pacman -R 包名

apt update ≠ apt upgrade：前者刷新“有什么可装”，后者才真的升级。新手最常见的事故是搞混这两个然后以为系统已经更新了。

十、磁盘空间：No space left on device 怎么查

标准排查顺序：

  1. df -h 找出是哪个挂载点满了；
  2. du -sh 该目录下/* | sort -h 一层层往下钻；
  3. 常见元凶：/var/log（日志没轮转）、/var/lib/docker（镜像和日志堆积）、被删但仍被进程占用的文件（lsof | grep deleted，重启对应进程才释放）；
  4. 不要直接 rm -rf /var/log/*，先确认日志服务和轮转配置。

十一、管道、重定向：把命令拼起来

写法 含义
cmd > file 标准输出覆盖写入文件
cmd >> file 标准输出追加
cmd 2> err.log 只把错误输出写文件
cmd > all.log 2>&1 输出和错误都写同一文件
cmd &> all.log 同上，bash 简写
cmd1 | cmd2 把 cmd1 的输出当 cmd2 的输入
cmd | tee file 一边显示一边存文件
cmd & 后台运行
nohup cmd & 后台运行且退出终端不中断

记忆点：2>&1 的意思是“把 2 号（错误）指向 1 号（标准输出）当前指的地方”，所以 > f 2>&1 的顺序不能反。

十二、压缩与解压

tar 的参数其实有规律：c 创建 / x 解压 / t 查看，z 是 gzip，f 后面跟文件名。

备份时用 -C 父目录 目录名 的形式，否则解压出来会带一串绝对路径，很容易覆盖错地方。

十三、远程传输：scp 和 rsync

rsync 源路径末尾带不带 / 语义不同：site/ 是把目录内容同步过去，site 是把目录本身放过去。

十四、效率技巧：让命令行变快

快捷键 作用
Tab 补全（连按两次列候选）
Ctrl + R 搜索历史命令
Ctrl + C 中断当前命令
Ctrl + Z 挂起到后台，fg 恢复
Ctrl + A / Ctrl + E 跳到行首 / 行尾
Ctrl + U / Ctrl + K 删到行首 / 删到行尾
Ctrl + W 删掉前一个单词
!! 重复上一条命令（sudo !! 超好用）

十五、危险命令清单（建议贴在显示器上）

命令 风险 替代做法
rm -rf / rm -rf /* 系统报废 永远不要用；删除前先 ls
rm -rf $VAR/ 变量为空时等于删根 改成 rm -rf "${VAR:?}/..."，为空则报错退出
chmod -R 777 / 权限体系崩塌 精确到目录，不要 -R 到根
chown -R user / 同上 同上
> /etc/passwd 清空用户库，系统无法登录 改文件前先 cp 备份
dd if=/dev/zero of=/dev/sda 整盘数据抹除 确认设备名，lsblk 核对
mkfs.ext4 /dev/sda 格式化错盘 同上
kill -9 1 杀 init，系统崩溃 重启用 reboot

保命技巧：重要操作前先 cp 备份，或者用 mv 改名而不是删；服务器上先 tmux/screen 再干活，断线不丢现场。

十六、七天练手清单

按顺序做完，命令行就算是入门了：

  • 用 pwd ls -la cd 在 /etc、/var/log、~ 之间自由走动
  • 用 mkdir -p 建三层目录，用 mv 改名，用 rm -i 删掉
  • 用 less 打开 /var/log/syslog（或 /var/log/messages），搜 error，跳到文件尾
  • tail -f 追一个日志，另开窗口 curl 一个请求，看日志动起来
  • 用 find / -name "*.conf" 2>/dev/null 找配置文件，用 grep -rn 搜内容
  • 写个 hello.sh，chmod +x 后跑起来，再用 755 / 644 对比结果
  • ps aux | grep 找到自己的进程，kill 掉它
  • systemctl status 看一个服务，用 journalctl -u 读它的日志
  • df -h 和 du -sh /* 对比，找出最占空间的目录
  • 用 scp 在局域网两台机器之间传一个文件

十七、新手常见报错速查

报错 常见原因 处理
command not found 命令没装 / 不在 PATH / 拼写错 apt install 包名；echo $PATH；which 核查
Permission denied 权限不够 id + ls -l 看，然后 sudo 或 chmod
No such file or directory 路径错 / 相对路径以为绝对 pwd 确认当前位置，用绝对路径
Is a directory 对目录用了文件操作 加 -r（cp -r / rm -r）
No space left on device 磁盘或 inode 满 df -h / df -i，再 du 找元凶
Text file busy 程序在跑，文件被占用 先停服务再替换可执行文件
Device or resource busy 有进程占用挂载点 lsof +D 目录 找到进程后再 umount
Too many open files 文件句柄数到上限 ulimit -n 查看，调 /etc/security/limits.conf
Connection refused 服务没起 / 端口不对 / 只监听本地 ss -tulpn 确认监听地址和端口
中文显示成方块或乱码 locale 没配 locale -a 看有没有 zh_CN.UTF-8，改 /etc/locale.gen 后 locale-gen

结语

命令行的学习曲线其实是前陡后缓：前十个小时最难受，过了那个坎，你会发现图形界面才是慢的那一个。

给新手的三句实在建议：

  1. 别背参数。记住命令名和用途，参数用时再 man，用三次自然就记住了。
  2. 每次操作前先 ls。这条能避免 90% 的“我好像删错东西了”。
  3. 在虚拟机或容器里练。docker run -it --rm debian bash 一条命令就有一个随时可以推倒重来的实验环境，练坏了删掉重来，成本为零。

下一篇打算写 tmux 和 shell 脚本入门——那才是把命令行从“会用”变成“用得爽”的分界线。
